# 文本导入导出、独立番茄钟与个人页实现要求

> 文档日期：2026-09-27  
> 对应项目：`日程安排`，当前程序版本 v1.3.4  
> 文档性质：需求、验收标准与 v1.3.4 发布记录。

## 1. 需求理解

本轮要完成三个用户可见的能力：

1. 用户能粘贴带 `1、2、3` 等编号的任务文本，或读取 Markdown（`.md`）/ Word（`.docx`）文件，预览后批量建立任务；也能把现有任务导出为 Markdown 或 Word。
2. 番茄钟拥有独立界面，开始计时、查看记录和调整参数不再依赖首页标题区与设置抽屉。
3. 增加类似 GitHub 贡献图的个人页，显示连续完成天数和每天完成的任务数。

这三个能力均应接入现有登录账号和任务数据，不另建一套待办应用。网页保持现有暖纸风格、中文为主的文案和手机端适配。

### 1.1 当前事实与影响

- 任务、按日期的完成状态、当日补充已保存在 CloudBase PostgreSQL，并按账号隔离。
- 现有番茄钟的主控在首页 `TO DO LIST` 旁，设置和最近七天统计在设置抽屉；专注记录按账号保存在当前浏览器的 `localStorage`，跨设备不可见。
- 单日任务完成一次；连续日期范围任务在每个日期独立完成。现有取消完成会删除对应完成记录，删除任务会级联删除其完成记录。
- 任务标题最多 160 字。导入文本不能绕过现有任务校验。

## 2. 产品结构与导航

登录后的主导航提供三个明确入口：**日程**、**专注**、**个人**。默认进入日程；刷新后可以恢复当前页面，页面地址也能直接定位到对应视图。未登录访问任一视图先进入现有登录流程，登录成功后返回目标视图。

```text
日程：日期、任务清单、完成操作、文本导入与任务导出入口
专注：大号倒计时、控制按钮、关联任务、参数、专注记录
个人：账号名称、连续天数、每日完成热力图、按日明细
```

桌面端导航放在稳定、易找的位置；手机端确保三个入口均可触达，点击区域至少 44px。切换视图不重置所选日程日期，不中断正在运行的番茄钟。页面间使用浏览器前进/后退时，视图与地址保持一致。设置抽屉继续承载账号、外观与句子等全局设置。

## 3. 编号文本导入与任务导出

### 3.1 导入入口与用户流程

日程页提供“导入任务”入口。用户可以直接在文本框粘贴多行内容，也可以选择 `.md` 或 `.docx` 文件读取文本。典型输入是：

```text
1、完成数学作业
2、阅读第二章
3、整理课堂笔记
```

系统逐行识别编号，把每一个编号项转成一条待创建任务。支持 `1、内容`、`1. 内容`、`1) 内容` 和 Markdown 的 `1. [ ] 内容` 等常见写法；编号须位于行首，序号按顺序递增。空行可忽略。没有编号的普通段落、缺号、重号或一项跨多行时，在预览中指出并允许用户修改原文后重新解析，不猜测其任务边界。本应用导出文件中缩进的“日期 / 时间 / 优先级 / 完成状态”行作为上一项的元数据读取，不另建任务。不得调用付费 AI 服务才能完成基础识别。

导入前选择目标日期，默认使用日程页当前查看的日期。对普通编号文本，首版每个识别项创建为该日期的**单日、普通优先级、未完成**任务；预览表格允许逐项修改标题、日期、优先级，或取消某项。本应用导出文件若带有可识别的日期范围与时间段，则在预览中还原并允许修改。确认前展示将创建的数量和每条任务的最终内容，确认后才写入当前账号的云端任务表。

### 3.2 解析与保存规则

- 读取 `.md` 时按 UTF-8 文本处理；读取 `.docx` 时提取正文中的编号段落和普通文本段落，兼容 Word 自动编号列表，不要求用户手工打出可见的数字。`.doc` 老格式首版不支持，提示转换为 `.docx`。
- 每个条目的编号只作边界标记，不进入任务标题。保留标题内的正常标点、中文、英文和空格；去除前后空白，不擅自改写内容。
- 识别空标题、超过 160 字的标题、无效日期及超出处理上限的输入时，定位到具体条目并阻止该条写入。HTML、脚本和 Word 宏不执行，预览使用纯文本渲染。
- 与当前账号同日期、同标题的已有任务在预览中提示“可能重复”，默认不创建；用户可以明确选择仍然创建。一次导入文本内部的相同条目同样提示。
- 批量写入应尽量原子化；若云端部分成功，明确显示成功和失败条目，并让重试只处理未成功的条目。导入不会删除或覆盖已有任务。
- 原有“复制本机事项到云端”属于旧数据迁移，应与这里的文本导入区分命名。

### 3.3 任务导出

日程页提供“导出任务”，可选当前查看日期、指定日期范围或全部任务，再选 Markdown 或 Word（`.docx`）。导出的是当前账号已有的任务清单，按业务日期和任务顺序排列，使用 `1、2、3` 编号；每个任务只列一次，标题后以缩进字段列出单日日期或完整起止日期、时间段、优先级，以及导出范围内各日期的完成状态。连续任务不能被误写为只存在某一天。导出范围内没有任务时生成说明为空的有效文件。

导出文件可再次作为导入来源：编号任务应被正确识别；日期、优先级等明确写出的本应用字段可预填到预览，但现有任务一律先做重复检查。导入默认**不自动设置为已完成**，即使原导出文件写有完成标记，也要在预览中说明这一点，避免导入操作无意改变个人页统计。首版不导出当日补充或专注记录。

导出的 Markdown 用 UTF-8，可在普通文本编辑器阅读；Word 文件可在常见 Word 阅读器打开。文件名包含导出范围与日期。文件不包含密码、令牌、内部用户 ID 或背景图片私有地址。

### 3.4 验收示例

- 粘贴上述三行文字，预览显示三条任务，确认后在所选日期创建三条未完成任务。
- `.md` 和 Word 自动编号列表各导入一次，编号不会出现在任务标题里；无编号段落或重复序号得到可定位的提示。
- 同一段文本重复导入，预览提示可能重复并默认跳过，用户明确选择后才允许再次创建。
- 导出当前日期和全部任务到 `.md` / `.docx`，内容与所选范围一致；从导出文件重新导入时能解析任务并识别已有任务。
- 超长任务、损坏的 `.docx` 或保存失败时显示具体错误，已有任务不被覆盖或删除。

## 4. 独立番茄钟界面

### 4.1 页面内容

专注页的主要视觉元素是大号倒计时和当前阶段（专注 / 休息 / 暂停）。同屏提供开始、暂停、继续、提前结束、开始休息等当前状态适用的操作。开始前可选择关联任务，并调整专注与休息时长、结束声音；默认值与现有功能一致。下方展示今日专注时长、完整轮数、最近七天趋势和历史记录。

从日程页进入专注页时，可携带当前任务作为关联项；用户也可选择“不关联任务”。专注完成不自动勾选任务。离开专注页后计时继续，所有页面都可看到不遮挡主要操作的小型剩余时间入口；点击可回到专注页。暂停时显示暂停状态，未开始时不显示悬浮计时器。

### 4.2 沿用现有计时语义

- 专注默认 25 分钟、休息默认 5 分钟；沿用现有 1–180 分钟专注、1–60 分钟休息的整数范围。
- 暂停和休息时间不计入专注时长。提前结束记录实际专注时长；完整轮数只在达到计划专注时长后增加。
- 倒计时按时间戳计算，后台运行或电脑睡眠后恢复时校正；超过预定结束时刻不多记时长。跨午夜时长按上海时区分摊到对应日期。
- 页面刷新、切换视图后恢复当前会话；退出登录时按现有逻辑暂停会话。
- 结束提示和声音遵从浏览器限制；关闭浏览器后不保证响铃。

### 4.3 数据边界

独立界面首版复用现有按账号分离的本机专注记录，不能把本机数字说成跨设备统计。若个人页展示专注数据，需先设计云端专注记录迁移、账号隔离和双设备避免重复计时；本轮个人页的连续天数只依据云端任务完成记录。移除旧首页主控与设置内重复统计时，历史本机专注记录必须仍能在同一浏览器的专注页看到。

### 4.4 验收示例

- 开始 25 分钟专注，切到日程和个人页、刷新专注页，计时不重启；暂停期间时长不增加。
- 先完成一轮，再提前结束 18 分钟，今日显示 43 分钟和 1 个完整轮次。
- 手机窄屏能操作全部控制按钮，悬浮入口不会盖住任务完成按钮或设置入口。

## 5. GitHub 风格个人页

### 5.1 信息与交互

个人页显示当前账号的称呼、**当前连续完成天数**、统计范围内的**总完成次数**和**每日完成热力图**。热力图默认展示最近 365 个自然日，按周排列；无记录的日期也显示空格。颜色深浅对应每天完成次数，旁边有图例。鼠标悬停或键盘聚焦某一天时显示完整日期和完成数；点击后展示该日已完成任务的名称与数量。手机端支持触摸查看，不依赖 hover。

当前连续天数的口径：一天至少完成 1 个任务日期实例，算作“有完成的一天”；从今天向前数，若今天尚未完成任何任务，则允许从昨天向前计算，今天完成后立即把今天纳入。中间任一自然日为 0 即中断。新账号显示 0 天。页面明确标注“连续完成天数”，避免与“连续登录天数”混淆。

每日完成数按云端 `todo_daily_completions` 中该日期为已完成状态的不同 `(task_id, completion_date)` 计数：单日任务算 1 次；连续任务在每天各算 1 次；同一天反复勾选同一任务仍只算 1 次。日期按 `Asia/Shanghai` 的业务日期归属，与日程页一致。取消完成后该日计数应减少，重新完成后恢复；明细和热力图同步更新。

### 5.2 历史记录与数据方案

现有完成记录依赖任务外键，删除任务会连带删除历史完成情况。为了让个人页的长期统计稳定，实施时需建立独立于任务生命周期的完成历史快照，至少保存账号、任务 ID、任务标题快照、完成日期和当前有效状态。已有完成记录上线时一次性回填；之后勾选、取消、改期和删除任务时同步维护，防止热力图与任务列表口径分叉。删除任务后历史已完成日期仍保留在个人页，并以标题快照展示；用户主动取消完成则撤销对应日期的有效完成状态。

历史表启用与现有表等价的账号级 RLS。个人页只读当前账号数据；大范围查询按日期聚合或分页，避免为绘制一年热力图下载全部任务及补充。统计加载失败时显示错误与重试入口，不能默默显示 0 天。网页标题与图例说明统计时间范围，范围外数据不影响“当前连续天数”计算。

### 5.3 验收示例

- 连续三天每天完成至少一项，显示连续 3 天；今天还没完成时，昨天的连续记录不在午夜立即变成 0。
- 同一天完成三个任务显示 3；同一连续任务在两天分别完成，两天各显示 1。
- 取消一项完成，热力图、总数、日明细和连续天数同步变化。
- 删除已完成任务后，历史日期仍显示原完成次数和标题快照。
- 两个账号相互看不到对方的热力图和明细；跨设备登录显示一致的任务完成统计。

## 6. 实施顺序与完成标准

1. 抽离日程任务和完成记录的数据读取接口，为文本导入导出与统计提供可复用的数据边界。
2. 设计并迁移独立完成历史快照，回填既有记录，核对任务列表与个人页的计数一致。
3. 建立三视图导航并迁移番茄钟界面，先保持已有计时记录与控制行为。
4. 实现编号文本粘贴与 Markdown、Word 读取，提供预览、批量建任务和两种格式的任务导出。
5. 实现个人页热力图、连续天数、每日明细和状态反馈。
6. 在桌面和手机宽度下验收导航、文件往返、跨日统计、账号隔离、刷新恢复与失败重试；通过现有 `npm run check`、`npm run test:focus`、`npm run test:features` 和 `npm run build`，并为新解析与统计规则补充有意义的测试。

完成的判定是：三个入口均可实际使用；粘贴的编号文本及 Markdown、Word 文件能识别为待创建任务，现有任务能导出为两种格式；番茄钟在独立页稳定运行；个人页连续天数与每日完成数符合上述口径，并且账号隔离和已有数据不受破坏。数据库迁移与静态发布已于 2026-09-27 按部署流程完成。

## 7. 待确认的产品选择

- 是否需要在预览中直接为导入任务设置“连续多日”和每日时间段？本文首版先支持单日任务及标题、日期、优先级调整。
- 是否需要通过导出再导入恢复完成状态或当日补充？本文首版只批量建立任务，避免不经确认修改历史统计。
- 个人页是否需要公开分享给其他人？本文按登录后仅本人可见编写，GitHub 风格只指贡献热力图的呈现方式。
