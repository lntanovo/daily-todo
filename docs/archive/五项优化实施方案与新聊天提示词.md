## 0. 执行前必读

### 当前基线

- 前端为 Vite + 原生 HTML/CSS/JavaScript；账号使用 CloudBase Auth；任务、完成记录、当日补充、个人热力图使用 CloudBase PostgreSQL。
- 番茄钟会话目前位于 `src/focus.js` 管理的按账号分隔的 `localStorage`；`src/focus-core.js` 已实现开始、暂停、继续、结束、跨午夜拆分和统计。`BroadcastChannel` 仅同步同浏览器标签页。
- `todo_tasks` 仅有单日 `single` 与每天出现的连续日期范围 `range`。完成记录的主键是账号、任务 ID、日期；个人页还使用独立的 `todo_completion_history` 快照表。修改排程必须验证历史统计不会被意外改写。
- 现有 Markdown / Word 导出是**可读的任务清单**，导入会创建未完成任务，不能作为完整恢复文件。每日补充保存在 `todo_daily_notes`；用户背景在私有对象存储。
- 2026-10-08 本地 `npm run build` 成功，但构建产物包含约 10.4 MB 的思源宋体 WOFF2 和一个约 875 KB 的 JS chunk。思源宋体当前只在任务标题用到，且 `font-display: swap`；霞鹜文楷已经分片。**构建文件大小不等于实际首屏下载量**，先测网络请求再决定如何优化。
- 当前工作区存在多处未提交改动及新增文件，包含 v1.3.4 功能。新聊天必须先运行 `git status`，确认每项改动来源；不得重置、覆盖或误删现有工作。

### 总体完成标准

五项功能均在现有应用中可实际操作，桌面和手机可用；现有任务、完成历史、补充、导入导出和背景功能继续工作。涉及云端表的改动使用新的版本化迁移，保持账号隔离与 RLS。每项先在测试数据上验证，再更新公网版本；发布记录中写明迁移版本、测试结果和仍存在的限制。

## 1. 首次打开速度

### 用户结果

手机第一次打开网站时，登录页和当天任务尽快可见、可操作；打开 Word 导入/导出或个人页时才加载对应的大型功能代码。暖纸视觉和任务标题字体尽量保持一致。

### 具体改动

1. 用生产构建和真实手机网络节流分别记录登录页、已登录日程页、个人页的请求瀑布、传输字节、LCP、INP 和 CLS；保存优化前后可复现的测量环境及截图。不要仅凭 Vite 的产物清单判断首屏。
2. 检查 `src/features.css` 的思源宋体请求。如果实际下载确实拖慢日程页，将其按常用汉字与其余字符切分为 WOFF2 子集，正确配置 `unicode-range` 和字体回退；复杂/罕见字仍须可读。保留字体许可证文件和 `font-display: swap`。
3. 检查 `index.html` 对 `src/profile.js`、`src/task-transfer.js` 的静态导入。让个人页和任务导入导出仅在首次打开时加载；当前 `docx`、`mammoth` 已使用动态导入，无需重复改造。查看最大的 JS chunk 的模块来源后再拆包，不靠调高 `chunkSizeWarningLimit` 消除警告。
4. 首页背景图保持现有压缩逻辑；确认自定义背景未阻塞主要文字与任务操作，并检查缓存策略与重复访问情况。

### 验收

- 同一设备/网络条件下，首屏传输量和可操作时间较基线有实测改善；目标建议为首屏传输量至少下降 30%，若做不到则附测量数据解释。
- 以真实测量为准，争取第 75 百分位 LCP ≤ 2.5 秒、INP ≤ 200 毫秒、CLS ≤ 0.1；没有足够真实用户样本时只报告实验室结果，不冒称达到线上百分位。
- 常见和罕见中文任务标题均正确显示；慢网、首次访问和重复访问都检查；Word 导入导出、个人热力图仍可用。

### 涉及位置

`src/features.css`、`assets/fonts/`、`index.html`、`src/profile.js`、`src/task-transfer.js`、`vite.config.js`；新增性能测量记录可放 `docs/`。

## 2. 番茄钟记录云同步

### 用户结果

同一个账号在不同设备看到一致的已完成专注记录。计时中的会话在刷新或换设备后可以恢复；同账号同时只能有一轮活动计时。已有浏览器记录可安全迁入云端，不丢失也不重复。

### 数据与流程

1. 新建版本化 PG 迁移，例如 `todo_focus_sessions`：`owner_id`、会话 `id`、阶段 `focus/break`、状态、计划/实际秒数、任务 ID 与标题快照、开始/运行起点/预定结束/实际结束时间、`segments`（JSONB）、`revision`、`updated_at`。任务 ID 不设级联删除外键，删除任务后仍保留专注历史。以 `(owner_id,id)` 为主键；为每个账号的 `running/paused` 状态建立唯一约束或等价的事务规则。启用账号级 RLS。
2. 将 `focus-core.js` 保持为纯计时/统计逻辑；增加云端仓储层，页面的开始、暂停、继续、结束由云端确认后成为权威状态。状态更新使用 `revision` 条件更新或事务函数解决两设备竞争；不能仅依靠 `BroadcastChannel`。
3. 当前运行中的倒计时仍按时间戳渲染。设备休眠、后台恢复、跨上海时区午夜时沿用现有截断与分摊规则。服务端保存的计划结束时间是上限，不能把休眠后的全部时间算为专注。
4. 首次登录检测本账号本机旧键 `daily-todo.focus.v1:<uid>`：展示待迁移会话数与预览，按稳定 UUID 幂等导入，云端成功读回后标记“已迁移”；保留本机备份一段恢复期。云端已有活动会话且本机也有活动会话时，显示冲突并让用户选择，不能默默覆盖或双算。
5. 网络断开时继续显示当前倒计时和“未同步”状态；新建及状态变更需要云端确认。若允许离线操作，则必须设计可靠的待同步队列和冲突规则；首版建议先禁止新的离线状态变更，并给出明确提示。
6. 专注页、迷你计时器、任务下方专注时长和最近七天统计统一读取云端权威数据。历史记录按日期分页，避免每次登录下载全部会话。

### 验收

- 同账号 A 设备完成一轮，B 设备刷新后看到同一时长与轮数；不同账号完全隔离。
- 两设备同时按“开始”，最终最多一轮处于运行或暂停；另一端看到明确冲突提示。
- 本机旧记录迁移两次也没有重复；迁移前后总专注秒数、跨午夜统计和任务关联一致；删除任务后历史仍在。
- 网络失败时页面不显示“已同步”；重连后明确恢复结果。

### 涉及位置

`src/focus.js`、`src/focus-core.js`、`index.html`、`src/profile.js`（仅在计划展示专注概览时）、`cloudbase/migrations/`、`tests/focus.test.mjs`；新增云端仓储及迁移测试。

## 3. 重复任务

### 用户结果

创建“每周一、三、五运动”或“每月 1 日交账单”后，相关日期自动出现任务，无需逐日复制。每次出现的完成状态和当日补充仍彼此独立；编辑或停止未来重复不清除过去完成轨迹。

### 首版范围与数据模型

- 保留现有 `single` 和 `range` 语义。新增 `recurring` 类型，规则首版支持“每周指定星期几”或“每月指定日期”，间隔固定为每 1 周/每 1 月；起始日必填，结束日可选。每月 29/30/31 日遇到没有该日的月份时**跳过**，不自动挪到月底。以 `Asia/Shanghai` 的业务日期判断命中。
- 新增 `todo_task_recurrences`，以 `(owner_id,task_id)` 关联 `todo_tasks`，保存 `frequency`、星期掩码或星期数组、月内日期、起始与可选结束日期、创建/更新时间。为 `todo_tasks.type` 和日期约束增加兼容 `recurring` 的迁移；所有新表启用 RLS。
- 日程查询的出现规则改为 `single/range/recurring` 统一函数。现有 `todo_daily_completions` 与 `todo_daily_notes` 继续以任务 ID + 业务日期保存，不为未来几年预生成大量任务行。个人页历史快照继续保持按日期计数。
- 编辑规则要在界面说明：编辑规则影响尚未完成的未来日期；已经完成的日期及其补充和完成历史不自动改写。停止重复通过设置结束日期实现；删除整个任务沿用明确确认和现有历史保留规则。首版暂不支持“只跳过某一天”的例外编辑，避免在没有例外数据模型时做出误导按钮。
- 导入/导出与备份应区别处理：普通编号文本导入仍为单日任务；完整备份必须保存重复规则；可读的 Markdown/Word 导出至少标明重复规则，重新作为普通任务导入时须告知不恢复规则。

### 验收

- 周一/三/五规则仅在对应星期出现；跨月、跨年和闰年正常；每月 31 日在 2 月不出现。
- 同一个重复任务周一完成，不影响周三状态；当日补充也互相独立。
- 修改未来规则后，历史完成日的个人热力图和明细不丢失；两个账号互相看不到规则。
- 现有单日与连续日期范围任务的增删改、完成状态不回退。

### 涉及位置

`index.html`（任务表单与日期筛选）、`src/calendar.js`、`src/task-transfer-core.js`、`src/profile-core.js`、`cloudbase/migrations/`、相关测试；建议新增纯函数 `src/recurrence-core.js`。

## 4. 快速录入、模板与删除撤销

### 用户结果与界面

日程页任务清单附近增加单行“快速添加”；回车把文本建成当前查看日期的普通单日任务。点击“更多选项”进入现有完整表单。模板入口不抢占首页主按钮，可从快速添加展开常用任务。删除后显示明确的撤销入口，并提供可恢复期限。

### 具体改动

1. 快速添加沿用现有任务标题 1–160 字、账号、日期和保存错误规则。空白不提交；云端保存失败保留原输入，不能只在页面上假装已创建。新增任务后焦点仍便于继续输入。手机输入法的确认键不能造成重复提交。
2. 模板首版保存在新表 `todo_task_templates`：账号、模板 ID、名称、任务标题、优先级、可选时间段、创建/更新时间。模板不存固定日期、完成状态或补充。用户可从已有任务存为模板、套用到当前日期、编辑名称、删除模板；账号级 RLS 和跨设备同步必需。
3. 删除撤销使用 `todo_tasks.deleted_at` 软删除：普通任务查询只返回未删除项；删除后显示约 8 秒的“撤销”提示，撤销将 `deleted_at` 置空。即使关闭标签页，也不会出现“用户以为删掉、实际没删”的情况。设置内增加“最近删除”（例如保留 30 天）可恢复。清理过期记录时，先明确任务、完成记录、当日补充和个人历史的处理方式；个人历史快照继续保留。清理可由受控后端任务执行，不能依赖用户保持浏览器打开。
4. 软删除迁移必须检查现有 `todo_completion_history` 同步触发器、任务外键及列表读写；恢复任务后原有补充和当前完成状态应如预期恢复。若采用其他可靠撤销方案，需达到相同的关闭标签页与跨设备一致性验收。

### 验收

- 快速连续添加两项后顺序正确；失网时输入保留并给出失败提示；不影响完整表单。
- A 设备保存的模板在 B 设备可用；模板应用后仍可独立编辑任务。
- 删除后立即撤销、刷新后从最近删除恢复、跨设备查看删除状态均正确；超期清理规则有测试且不会误删个人完成历史。
- 键盘、触摸、窄屏均可操作；不恢复首页已否决的大块永久底板，维持 Warm Paper 视觉和已有背景可读性。

### 涉及位置

`index.html`、`src/app-shell.css`、`src/settings.css`、任务保存/删除逻辑、`cloudbase/migrations/`、浏览器交互测试；建议抽离任务数据仓储以减少 `index.html` 内的重复读写逻辑。

## 5. 完整备份与恢复

### 用户结果

用户下载一个可验证的备份文件，必要时可在当前或新账号中预览并恢复自己的任务及历史。现有 Markdown/Word 清单继续用于阅读/分享，页面要清楚说明它**不是完整备份**。

### 文件与恢复规则

1. 采用版本化 `.zip` 备份：`manifest.json`（格式版本、导出时间、记录计数和校验信息）、`data.json`（任务、重复规则、完成记录、完成历史快照、当日补充、专注会话、模板、可安全迁移的偏好）。若当前账号有私有背景图，加入 `background/` 文件与元数据；无法读取时导出失败或明确要求用户确认“无背景的不完整备份”，不能悄悄称作完整。
2. 不导出密码、登录令牌、CloudBase 密钥、注册台账，也不把旧 `owner_id` 当作恢复后的权限依据。下载尽量在浏览器内生成，不上传到第三方服务；备份文件包含个人信息，下载前提醒用户妥善保存。
3. 恢复先解析、校验版本/大小/条数/校验和，再显示预览：新增、重复、冲突、跳过与错误数。首版只提供**合并恢复**，默认跳过同 ID 数据，用户可逐类选择需要恢复的内容；不提供一键覆盖整个账号。恢复目标账号统一由当前 CloudBase 登录会话决定。
4. 按依赖顺序恢复任务、规则/模板、当日补充、当前完成状态、历史快照、专注记录、偏好和背景。专注会话以稳定 ID 幂等去重；当前账号已有活动计时和备份中的活动计时发生冲突时要求用户选择。完成状态与历史快照恢复应通过事务或受控服务端入口保证一致，不绕开现有历史触发器，也不把取消完成的旧快照误设为有效。
5. PG 数据尽量在事务中提交；背景对象存储与 PG 不能假定共用事务，需要先暂存、提交后切换引用，失败时清理孤立文件。恢复过程中显示进度，失败后给出可重试结果，不能仅报“部分成功”而无法定位。
6. 备份应包含已软删除任务或至少明确“最近删除”是否纳入；首版建议纳入，使 30 天内可恢复状态不因跨账号迁移丢失。备份文件格式文档留在仓库，便于以后升级。

### 验收

- 用含单日、连续、重复、已完成、当日补充、专注记录、模板、自定义背景和最近删除任务的测试账号导出；在空账号恢复后逐项核对数量和内容，个人热力图总数一致。
- 同一备份重复合并恢复不产生重复任务、专注会话或完成计数；损坏、超大、未知版本或恶意 ZIP 路径被拒绝，且不会写入部分脏数据。
- 两个账号的导出/恢复不能读取对方私有数据；恢复后的账号级 RLS 仍成立。

### 涉及位置

`src/task-transfer.js`（仅可复用文件交互，不把任务清单格式冒充备份）、`src/daily-notes.js`、`src/focus.js`、`src/appearance.js`、`cloudbase/migrations/`、新的备份格式与恢复模块、相关单元与浏览器测试。

## 7. 可直接发给下一个聊天的提示词
