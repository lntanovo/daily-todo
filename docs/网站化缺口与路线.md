# 网站化缺口与路线

## 现在已经有的

- 可以在电脑和手机浏览器中打开的待办页面。
- 单日事项、时间段共同任务、按天独立完成、周切换和两套主题。
- 浏览器本地保存，刷新后不丢；异常数据保护和窄屏适配已经完成。
- Vite 构建脚本，可生成适合云端托管的 `dist` 文件夹。

## 真正成为“人人可访问、各自有账号”的网站还缺什么

1. 云端环境：承载网页、数据库和用户身份认证。
2. 用户登录：首版建议邮箱＋密码，并保留验证码注册与找回密码入口。
3. 云数据库：任务和每天的完成记录不能继续只放在浏览器里。
4. 数据隔离规则：每个人只能读写自己的事项，不能看到别人的数据。
5. 本地数据迁移：用户第一次登录后，可把原浏览器中的事项安全迁入云端。
6. 正式部署：把构建后的页面上传到 CloudBase，得到可分享的 HTTPS 地址。
7. 上线验证：分别用两个账号确认数据互相看不到，再检查刷新、跨设备和手机显示。

## 已选方案

- 国内用户优先：腾讯云 CloudBase。
- 前端：继续保留现有 HTML/CSS/JavaScript 视觉和交互；后续接入 `@cloudbase/js-sdk`。
- 数据库：CloudBase 文档数据库，使用 `tasks` 和 `daily_completions` 两个集合。
- 后端：首版不写云函数。浏览器登录后直接访问数据库，安全由用户身份和数据库规则保证。
- 域名：先使用 CloudBase 提供的免费 HTTPS 地址；确认长期使用后再考虑购买域名和备案。

## 推荐的数据结构

### tasks

- `_id`：CloudBase 文档 ID。
- `ownerId`：当前登录用户 ID。
- `title`：事项内容。
- `type`：`single` 或 `range`。
- `date`：单日事项日期。
- `startDate` / `endDate`：共同任务的日期范围。
- `createdAt` / `updatedAt`：创建与修改时间。

### daily_completions

- `_id`：完成记录 ID。
- `ownerId`：当前登录用户 ID。
- `taskId`：对应的任务 ID。
- `date`：完成的是哪一天。
- `completed`：是否完成。
- `updatedAt`：最后修改时间。

## 当前阻塞点

CloudBase CLI 已安装并发起登录，但腾讯云授权必须由账号本人在浏览器中完成。授权后才能安全地取得准确的环境 ID、开启登录方式、建立数据库规则并发布网站；在此之前不应编造环境 ID或密钥。
