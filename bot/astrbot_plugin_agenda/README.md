# astrbot_plugin_agenda

私聊一句话记日程（先回执、确认后写云端）、开机补拉关机期间漏掉的私聊，并可在指定 QQ 群里**静默旁听**抽取日程；其余群仍由 AstrBot 正常陪聊。

## 行为边界

| 群 | 陪聊 | 入库抽取 | 提醒 |
|---|---|---|---|
| `chat_groups` | ✅ AstrBot 原生处理 | ❌ | ❌ |
| `watch_groups` | ❌ **绝不发言** | ✅ | ✅ |
| 其他群 | ❌ | ❌ | ❌ |

`watch_groups` 里的消息走一条专用 handler，结尾固定执行 `event.stop_event()`，
即使被 @、被回复、被戳也不会产生任何回复。

## 安装

1. 把整个目录放到 `AstrBot/data/plugins/astrbot_plugin_agenda/`
2. 重启 AstrBot，或在 WebUI「插件」页重载
3. 进入插件配置，填 `watch_groups`（静默群号）与 `chat_groups`（陪聊群号）
4. 在 AstrBot「机器人 → OneBot v11」确认反向 WS 已连通
5. 在「访问控制 → 白名单 ID 列表」里**加入所有 watch_groups 的群号**
   （否则白名单阶段会在插件看到消息之前就终止事件）

> 关键：`watch_groups` 必须同时在 AstrBot 的 `id_whitelist` 里，
> 否则 AstrBot 的 WhitelistCheckStage 会先 `stop_event()`，插件收不到消息。
> 静默由插件保证，不依赖白名单。

## 私聊记日程（v1.7）

主号（`admins_id`）私聊机器人说一句，例如：

```
周五 23:59 交操作系统作业3
周三下午三点讲座
11 月 20 号截止报名
```

也可以直接甩一整段通知进来——**一段里有几件事就记几件**：

```
【线下培训通知】……
1、学习贯彻习近平党建思想专题报告
时间：11月17日（周二）16:30
2、学习贯彻党的二十届五中全会精神专题报告
时间：12月1日（周二）16:30
3、……
```

机器人先回执、不直接落库：

```
先跟你对一下，这次一共 4 条：
1. 学习贯彻习近平党建思想专题报告
   2026-11-17（周二） 16:30
2. 学习贯彻党的二十届五中全会精神专题报告
   2026-12-01（周二） 16:30
……
回「1」全部存；只存其中几条就回「1 3」；回「2」全都不要。
```

- 回 `1` / `确认` / `好` / `全部`：全部写入云端 `todo_tasks`，站点立刻可见；
- 回 `1 3` / `只存 2、4` / `第3条`：只写这几条；
- 回 `2` / `取消`：丢弃草稿；
- `重试`：模型这次没解析出来时，拿原文再跑一遍；
- 想改：直接再说一句，草稿会被替换（同一会话只保留最新一条）。

### 为什么不靠"模型自己数"（v1.7 的结构性改动）

一条消息里有四件事却只记下一件，根因不是模型笨，而是**旧 schema 只有一个 `item`**：
模型就算看懂了也只能交回一条。现在（`capture.py`）：

1. **先切分再问模型**：按空行/列表项把原文切成块，凡是带日期或时刻的块编号成
   `[S1]..[Sn]`，prompt 里明说"每个编号都要有一条结果"；
2. **覆盖校验**：模型少答一个编号，代码当场算得出来，换成小 prompt 只补问漏掉的那几段；
3. **闲聊/日程双保险**：模型给 `kind`，代码再用"有没有带时间的段落"兜底，两边冲突时
   按日程走、宁可多问一句；某段其实是吐槽的，模型回 `skip` 即可；
4. **不确定就反问**：像任务但没日期 → 直接问"哪天"；模型调用失败 → 留草稿等「重试」，
   绝不悄悄放行到闲聊（以前这种消息会"看起来没反应"）。

> 推理型模型（`reasoning_content`）遇到长 prompt 会把 token 全花在思考上、`content`
> 返回空串。分段+补抽顺带解决了这个问题：补抽的 prompt 短，一次只问 1–4 段。

相关配置：`capture_provider_id`（抽取专用模型，建议比陪聊模型聪明一档）、
`capture_repair`（漏段自动补抽，默认开）、`capture_max_segments`（默认 12 段）。

写入需要三个配置项（Dashboard → 插件 → 配置）：

| 配置 | 说明 |
|---|---|
| `cloud_env_id` | 日程站点所在的 CloudBase 环境 ID |
| `cloud_api_key` | 服务端 Key，只存本机，不要外传 |
| `owner_id` | 写入目标账号 uid（`lnreg_…`），填错会写到别人名下 |

写入前按「同账号 + 同日期 + 同标题」查重，重试不会写出两条。

## 开机补拉

电脑关机期间收到的私聊不会自己进插件。插件启动后会：

1. 等 OneBot 连通，用 `get_friend_msg_history` 拉最近一页（默认 200 条）私聊；
2. 只留主号（`admins_id`）发的、水位之后的消息，逐条走同一套解析；
3. 解析出日程的进 `catchup` 队列，**逐条问确认**，确认后才写云端（同样查重）；
4. 超过 `catchup_max_age_days`（默认 7 天）的只在开头汇总条数，不逐条打扰。

相关配置：`catchup_enabled`、`catchup_max_age_days`、`catchup_history_count`、
`catchup_max_items`。首次启用时以当前时间为水位基线，不会把历史聊天全问一遍。

## 到点追问「完成了吗」

任务过了自己的时间还在今天没勾完成，机器人会私聊问一次：

```
⏰ 这 2 项到点了，完成了吗？
1. 交实验报告（15:30）
2. 去代课（16:20）
回「完成」全部标完成；只完成其中几条就回编号，比如「1 3」；回「没做」就不再问。
```

- 回 `完成` / `做完了` / `搞定`：写入 `todo_daily_completions`，站点上的勾会跟着亮；
- 回 `1` / `1 3` / `第2条`：只标这几条；剩下的在有效期内还能再回；
- 回 `没做` / `还没` / `算了`：这次不问，任务仍留着重试；
- 同一条任务同一天**只问一次**（`followups` 表记着），到点后等 `followup_grace_min`
  分钟再问；关机太久（默认 12 小时）的就不追了。

配置：`followup_enabled`（默认开）、`followup_grace_min`（15）、
`followup_check_sec`（300，每次检查读一次云端）、`followup_max_items`（6，同时到点的合并成一条）。

> 完成状态写的是站点同一张 `todo_daily_completions`（主键 `owner_id + task_id + completion_date`），
> 完成历史由数据库触发器维护，所以 bot 打勾和你在网页上打勾是同一件事。

## 每日任务简报（对话设置）

不想等到截止日才被提醒，可以直接跟机器人说：

```
每天 9 点提醒我最近有什么任务
每天晚上八点给我发任务清单
取消每天提醒
```

- 到点后机器人主动私聊发一份任务简报：逾期 / 今天 / 未来 7 天；
- 时间存在本地 `state.daily_push_time`，可以随时用一句话改；
- 那天电脑没开，**开机后会补发一次**（QQ 链路依赖电脑在线；云端企业微信早报不受影响）；
- 也可以用指令：`/每日提醒 09:00`、`/每日提醒`（查看）、`/每日提醒 关`。

窗口长度由 `daily_push_days` 控制（默认 3 天）。

## 指令（仅 admins_id 可用）

| 指令 | 作用 |
|---|---|
| `/任务` | 云端任务总览：逾期 / 今天 / 未来 7 天（含每条任务的提醒时间） |
| `/日程` | 同 `/任务`（保留旧名字，已改为读云端） |
| `/提醒` | 查看云端提醒设置：早报、晚间收尾、提前几天、免打扰 |
| `/每日提醒 09:00` | 设置每日任务简报时间；不带参数查看，`/每日提醒 关` 关闭 |
| `/绑定` | 把当前会话设为提醒投递目标（在你的私聊或"收件箱群"里发一次） |
| `/详情 <id>` | 某条群聊抽取日程的来源原文与消息 id |
| `/完成 <id>` | 标记完成，取消后续提醒 |
| `/取消 <id>` | 取消日程与提醒 |
| `/待确认` | 置信度不足、尚未提醒的群聊条目 |
| `/状态` | 静默群、陪聊群、今日 token 用量、投递目标 |

## 数据

`AstrBot/data/plugin_data/astrbot_plugin_agenda/agenda.db`（SQLite，WAL）

- `messages`：群聊原文，先落库再调用模型
- `events`：群聊抽取结果，带 `confidence` 与 `source_msg_ids`
- `reminders`：提醒队列
- `pending`：私聊待确认草稿（确认后删除，真相只写云端）
- `catchup`：开机补拉队列（`queued → asked → done/skipped`）
- `state`：投递目标、token 用量、私聊水位、日报日期

任务本身永远只存在云端 `todo_tasks`，站点、`/任务`、企业微信提醒读的都是这一张表。

## 成本

用 `deepseek-flash`：单批 40 条消息约 0.005 元；每日 token 预算到顶后只入库、不调模型。
